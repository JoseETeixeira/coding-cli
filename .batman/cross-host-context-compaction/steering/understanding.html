Compaction
without amnesia

Can Codex and Claude Code shed stale transcript tokens while staying safe inside large, intertwined systems? Yes—but only when conversation is treated as a cache, not the source of truth.

Conditional yes

Keep hot state small. Keep exact knowledge durable and re-readable.

Both hosts preserve a structured continuation after compaction. Neither guarantees verbatim retention of every code relationship or tool result. Safety comes from exact source, tests, approved artifacts, deterministic pointers, and a bounded post-compact re-read.

02

What survives—and what does not

Not safe to assume

  • Exact code read earlier or full tool output
  • Every negative finding or cross-system invariant
  • Claude path-scoped rules before their files are reread
  • A semantically retrieved memory is current or authoritative
  • Repository hook files are active merely because they exist

Durable recovery sources

  • Current source, tests, Git state, and active snapshots
  • Approved understanding, PRD, ADR, and task artifacts
  • Explicit task/artifact/memory identifiers
  • Root host instructions that are re-injected
  • Focused, bounded source and memory reads after compaction

04

Observed gaps

Gap A

No bounded continuation contract

Current policy establishes authoritative artifacts and pointers, but no host lifecycle currently assembles or injects a small post-compact continuation state.

Gap B

“Compact” memory is unbounded

task_context(top_k=8) returns full stored text. One relevant call injected about 8.9K approximate text tokens before response metadata.

Gap C

Canonical is not activated as one plugin

Claude uses environment pointers and global source-path hooks; Codex uses a separate shim/config. The shared hook file is not sufficient by itself.

Architecture risk is required, not optional. This request crosses memory API contracts, source-of-truth policy, lifecycle hooks, host configuration, packaging/trust, test harnesses, and rollback. A blind 64K setting is not yet justified for intertwined codebases.
